# 声音设计谱 · AUDIO-DESIGN

> 这是**音频层的唯一规格书**。`code/src/audio/audio.js` 必须与这张表一致。
> 任何"感觉声音不对"的调整，都要先改这张表，再改代码。

---

## 0. 总原则

1. **一个数驱动全部**：`tension = max(恐惧值, clamp01(1 − 身影距离 / 80))`
2. **所有增益变化**：`setTargetAtTime(target, now, τ)`，`τ = 0.35s`
   —— 直接赋值 `.value` 会产生咔哒声，是本项目最不可原谅的技术错误。
3. **静默是武器**：张力最高时**不是最吵**，是环境声被"闷住"到几乎消失。
   → 因此削减必须主要发生在 **低通截止频率** 上，而不是把增益压成 0。
4. **预兆纪律**：显形前 0.4 秒必须先有声音事件（crack 或呼吸速率突变）。

## 2. 波形整形的构造（关键实现说明）

### 2.1 呼吸包络（非对称）

不能直接用正弦 LFO 驱动增益——那听起来像"呼—吸—呼—吸"的电子音。
需要**吸气短促、呼气绵长**：

```
一个周期归一化为 θ ∈ [0, 1)：
  g(θ) = exp(−((θ − 0.06) / 0.045)²)            // 吸气：尖峰，宽 4.5%
       + 0.55 · exp(−((θ − 0.34) / 0.150)²)     // 呼气：宽而缓，宽 15%
```

然后把这条曲线烘焙进一个 `WaveShaperNode` 的 `curve` 数组（长度 1024）。
LFO（正弦）→ WaveShaper → 缩放增益 → 接到 `breathVCA.gain`。
**这样只需改 LFO 频率，呼吸节奏就整体变化。** 这是本设计最省事的一点。

### 2.2 心跳包络（双峰 lub-dub）

```
g(θ) = exp(−((θ − 0.05) / 0.045)²)             // lub
     + 0.68 · exp(−((θ − 0.31) / 0.055)²)      // dub
```

同样烘焙进 WaveShaper。LFO 频率 = BPM / 60。

### 2.3 为什么用波形整形而不是 `setInterval` 调度

用定时器调度会有累积漂移，且无法在张力突变时平滑改变速率。
LFO 的速率变化是**连续可调**的，且天然与音频时钟同步。

## 3. 一次性音效规格

| 名称 | 触发条件 | 合成 | 时长 | 峰值增益 |
|---|---|---|---|---|
| `sting` | 身影因"被注视"消失；或逼视失败 | 3 个失谐锯齿（cb 220→40 Hz 下扫，间隔 ±7 cent）+ 共振低通 Q12 + 噪声爆 | 0.9 s | 0.55 |
| `stingSoft` | 身影自然消失 | 同上，扫描范围减半，无噪声爆 | 0.6 s | 0.30 |
| `climax` | 距离 < 4 m | `sting(1.0)` + 全频噪声墙（0.5 s 上升）+ 反向膨胀 | 2.4 s | 0.95 |
| `crack` | 每 25–70 s 随机；显形前 0.4 s 必发 | 噪声爆 → 带通 300 Hz Q4 | 1.5 s 衰减 | 0.18 |
| `snap` | 与脚步随机绑定（约 12%） | 亮噪声爆 → 带通 1800 Hz | 0.12 s | 0.14 |
| `footstep` | 头部摆动相位过零点；音色随地表切换（pathInfluence > 0.5 = 路面） | **路面**：躯干 74 Hz±8% 下扫 0.13 s + 中频拍 620–1240 Hz 带通（Q 1.2–1.9，起点 0–12 ms 随机）0.11–0.16 s；**林地**：软躯干 62 Hz±8% + 3–5 个亮碎裂 1700–3200 Hz（85 ms 窗内随机错开，各 0.04–0.09 s）+ 沙沙尾 2600 Hz 0.3 s。每步电平 ±15%、左右脚交替 ±6% | 0.13–0.35 s | 路面 0.16 / 林地 0.11（× 速度系数 × 抖动） |
| `bell` | 进入神龛 30 m 内，每 20 s 最多一次 | 正弦 440 + 660（五度）→ 长衰减 | 2.2 s | 0.12 |
| `rustle` | 走过草丛（预留） | 亮噪声爆 → 带通 2600 Hz | 0.35 s | 0.10 |
| `crow` | 环境骰子：`crowInterval` 25 s（张力 0）→ 150 s（张力 1），**随张力变稀** | 亮噪声 → 窄带通 Q8–12，中心 2–3 声连叫各做 1150–1410 → 680–920 Hz 的 0.16 s 下扫（嘶哑感 = 扫频 + 噪声毛边，纯振荡器扫频听起来是"飞碟"） | 0.6–1.0 s | 0.05 |
| `insect` | 环境骰子：`insectInterval` 14 s（张力 0）→ 65 s（张力 1），随张力变稀 | 亮噪声 → 窄带通 Q14（4.2–5.8 kHz）→ 方波 LFO 22–30 Hz 调幅（蟋蟀翅摩）→ 串联包络 0.1 s 起收 | 0.6–1.5 s | 0.016（人耳此频段最敏感，必须比脚步低一个数量级） |

**噪声双通道**（§2 预着色的补充）：连续层（环境/风/雨/呼吸/心跳/耳语）永远走暗原料（`noiseHP 55 → noiseLP 780`）；一次性音效里中心频率高于 900 Hz 的瞬态自动升级走亮原料（`noiseHP 55 → noiseLPBright 5500`）。成因：snap/rustle/footstep 碎裂的频段在 1.5 kHz 以上，暗原料在 780 Hz 已被削尽，不分通道则所有瞬态退化为同一种闷响（"登登登"问题的第二根因，第一根因是零抖动）。

**噪声相位随机**（`_makeNoise` 的补充）：每次调用 `_noise()` 时对噪声 buffer 做一次随机循环移位。成因：buffer 是**同一个对象**，而 `src.start(t0)` 不带 offset，所以每个一次性音效都从 buffer 的 t=0 起播 —— 两次脚步读到的是同一段噪声的同一段相位，步间差异只剩增益与中心频率的 ±15%，波形本身高度重合。离线探针实测路面两步相关 **0.985**（阈值 0.98）把这个"伪随机"抓了出来：随机只加在参数上、没加在原料上。移位后降到 0.72–0.89。纯循环移位不改变白噪统计特性，交叉淡化仍成立，循环点依然无咔哒。

**姿态 → 响度接口**（移动姿态系统的音频面）：脚步力度乘 `(0.25 + 0.75 × noiseLevel)`。`noiseLevel` 由 controller 汇总（静步 0.22 / 蹲下 0.12 / 正常走 1.0，再乘一个速度因子），下限 0.25 是刻意留的：蹲着走如果力度趋近 0，脚步音完全消失 —— "完全没有声音"比"很轻的声音"更假，玩家会意识到声音被关掉了，而不是自己被藏起来了。同一份 `noiseLevel` 也被 director 拿去加权 `sinceTravel`（"连续行进"触发规则的燃料）：静步走 10 m 对该规则的贡献只相当于正常走 2.2 m。**慢不是惩罚，是把暴露换成时间。**

**动物声的方向与 crack 相反 —— 这不是笔误**：`crack` 间隔随张力**缩短**（75 → 16 s，它是危险的预兆）；乌鸦与虫鸣的间隔随张力**拉长**（乌鸦 25 → 150 s，虫鸣 14 → 65 s）。鸟叫虫鸣是"安全的标记"，森林的安静本身就是恐怖的度量：玩家说不出为什么害怕，但他听得见鸟不叫了。这是"静默是武器"的声学形态。同时两者的事件功率也随张力衰减（×1 − 0.6·tension / ×1 − 0.5·tension）：即使响了，也更远、更弱。

**虫鸣的包络必须串联，不能写在 LFO 的 AudioParam 上**：连接到 AudioParam 的信号是**叠加**在参数值上的，不是调制。v1 把起音包络写在 LFO 连接的同一个 gain 上，t0 时刻参数从 0 直接跳到方波满幅 ±0.016，包络 0.0002 的缓起盖不住 —— 每段虫鸣开头一记 -36 dBFS 的咔哒，单独听像虫子，连续听像"有人每两秒按一下打火机"。正确接法：`vca(LFO 调幅) → env(包络) → fx`，包络整形的是包含 LFO 的整个信号。探针用 `__onsetPeak`（头 10 ms 峰值 < 整段峰值 40%）永久看守这一类错误。

### 3.6 #26 新增三层：雨打树叶 / 雷空间化 / 女鬼呼吸

**① 雨打树叶（`rain-tick`，update 里调度的离散滴答）**：冠层雨声的物理本质是一颗颗水滴砸在针叶上的**撞击**，是有事件的，不是一片均匀的沙。连续层已有 body/detail 两路，再铺高频连续噪声只会把 2–4 kHz 推向验收线；离散滴答占空比极低（每声 18–48 ms），对总频谱均值几乎不动，但"淅淅沥沥"的字面意思由它们读出。实现：`update()` 里按 `rainTickRate`（天气 0→1 为 2.0→9.0/s，走 rainCurve）调度，每响复用 `_burst`（自动亮原料 + 4 kHz 低通护栏）：中心 2300–5200 Hz 随机、Q 6–11、电平 `rainTickLevel 0.028 ×(0.6–1.4) × (1 − 0.8·tension)`。间隔抖动 ±45%（固定间隔的滴答是节拍器）。**雨停必须滴答停**（与 detail 同系数退场，否则剩下"细碎的电流声"）。

**② 雷空间化（`_thunder(t0, near, pan)`）**：`Lightning._strike` 本来就算出了方位角 `az`，现在把它随雷声队列一起入队，到期回调改为 `onThunder(near, az)`。main.js 端换算声像：雷的方向 `(sin az, cos az)` 点乘玩家右方 `(cos yaw, −sin yaw)` = **sin(az − yaw)**，正 = 右。三层（滚动/脆裂/冲击）必须过**同一个**事件级 StereoPanner——分头直连 fx 的话雷会被撕成三个方位。**远雷声像收窄**（`thunderPanFar 0.55 → 1` 随 nearness）：方向感来自高频耳间声级差，而高频在大气里衰减最快，6 km 外的雷只剩无方向性的低频——硬 Pan 会让它变成"右声道音箱"而不是"那个方向的雷"。pan 参数默认 0：storm-probe 以单参数重放这条链，`Number.isFinite` 防线保证 NaN 永远进不了 AudioParam。

**③ 女鬼呼吸（`ghost-breath`，`setGhost(接近度 × 显形不透明度)`）**：结构与玩家呼吸同构（暗噪声 → 带通 → 低通 → VCA ← 整形 LFO），但三个数处处反着：频段更低（350 vs 520 Hz，"冷"在声学上就是低）、速率更慢且**越近越慢**（0.21 → 0.13 Hz；玩家是越怕越快——一件逼近你的东西呼吸越来越沉，比越来越急错得更多）、呼气拖得反常地长（GHOST_BREATH_CURVE：呼峰在 0.46 处、σ 0.24，玩家的在 0.34、σ 0.15）。增益用 prox²（7 米内才浮出来，出现得晚才有"贴上来"的骤然感）；**必须乘显形不透明度**——它溶解时"它"就不在了，只看距离会挂一层无主的呼吸。驱动独立于 setTension：玩家自己的紧张和"它在附近"是两件事。

新增 `tools/snd-probe.mjs`（18 断言）看守这三层：滴答的存在性/频段/时长/电平护栏/雨停即停、呼吸链节点/增益收敛/速率方向、雷的声像器唯一性/pan 数值/默认 0/端到端 sin(az−yaw)/队列带 az/director 喂给值。

## 5. 验收方法

1. 在 `?debug=audio` 下，每秒把当前参数打成一 CSV 行：
   `t, tension, ambientGain, ambientLPF, breathGain, breathHz, heartBPM, droneGain, whisperGain`
2. 用张力脚本把 tension 从 0 线性推到 1（60 秒），导出 CSV。
3. 抽查 5 个采样点与本文档第 1 节的表对照，**误差必须 < 10%**。
4. 人耳验证：全程不应出现任何"咔哒"、"爆音"、"断续"。
5. `node tools/audio-probe.mjs`（静态估算，已纳入雨 body/detail/滴答/女鬼呼吸；
   fx 支路层带 bypass 标记，不被总低通误夹）+ `node tools/snd-probe.mjs`
   （真实页面运行时，18 断言）+ `node tools/step-probe.mjs` + `node tools/storm-probe.mjs`
   —— 改信号链前后都要跑，全绿才算过。
