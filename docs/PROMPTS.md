# 提示词上下文 · 雾林回环

> 这份文档回答：**「我想把上面那个恐怖想法交给 AI 做出来，我到底该说什么？」**
>
> 它参照了 Dan Greenheck 用 Claude 造出 Tidewater 的方法论（见 `E:\AiStudy\tidewater\PROMPTS.md`），
> 并针对**恐怖游戏**这一类型做了重构。恐怖项目的 prompt 与图形项目的 prompt 有一个根本区别：
>
> > **图形项目靠"把东西画对"推进；恐怖项目靠"把东西藏起来"推进。**
> > 所以指标不是「像不像 Unreal」，而是**「玩家在第几秒开始不安」**。

---

## 0. 先吸收 Tidewater 的三条经验（否则这套 prompt 会用歪）

| Tidewater 的做法 | 迁移到恐怖项目 |
|---|---|
| **① 把上限钉死**："你能交付的最佳 AAA 体验，对标 Unreal" | 同样要钉上限，但钉的是**体验**不是画质：<br>"让玩家在第 90 秒之前无法确定自己是不是看到了什么" |
| **② 项目宪法承载 90% 约束** | 见本仓库 `CLAUDE.md`。**恐怖设计铁律必须进宪法**，不能只写在对话里 |
| **③ 让 agent 能"看见"自己的产物** | 图形项目看渲染图；**恐怖项目还必须"看见"时间轴**——<br>所以要求 agent 输出**恐惧曲线/声音曲线/显形日志**，而不是只有截图 |

**关键差异**：Tidewater 的验证物是**一张图**。恐怖项目的验证物是**一段时间**。
所以我们的 prompt 必须强制 agent 产出**可回放的时间轴证据**（见第 5 节）。

## 1. 项目宪法（对话前的隐式上下文）

完整版见 `docs/CLAUDE.md`。**把那份文件放进仓库根目录**，此后对话里的 90% 就可以是"废话"：

```
# 项目宪法摘要（完整版见 CLAUDE.md）

角色：实时图形工程师 + 恐怖游戏设计者。客户懂审美不懂代码，
      说"这里怪怪的"时必须自己判断是哪个参数。
技术：Three.js(WebGL2) + Vite + 纯 ESM。依赖只允许 three。
      零外部素材，几何/贴图/音频全部程序化。
      后处理用 DOM 叠加层，不用 EffectComposer。
风格：Tab / 单引号 / 分号，中文注释解释"为什么"。
      可调数字必须进 config.js，不许有魔法数字。
铁律：① 第一次出现必须不完整 ② 声音先于画面 0.4s
      ③ 只有 CLIMAX 允许贴脸 ④ 静默是武器
      ⑤ 恐惧来自玩家的选择（他转身 / 他不看）
验证：截图 + 显形日志 + 声音曲线三者缺一不可。
音频：全程序化；音量变化一律 setTargetAtTime；AudioContext 必须手势后创建。
```

## 2. 主链 prompt（7 条，从零到可玩）

> 每条都把**上限**或**底线**钉死。不要写"做一个恐怖游戏"，要写"做到什么程度才叫完成"。

| # | Prompt（可直接复制） | 产出 | 验收（这句话最重要） |
|---|---|---|---|
| **P1** | **做你能交付的最好的森林恐怖体验。它不靠跳脸吓人，靠"玩家开始不确定自己看见了什么"。技术栈 Three.js + Vite，零外部素材，几何贴图和音频全部程序化生成。** | `src/core/` + `src/world/terrain.js` | 打开页面 1.5 s 内出画面，没有任何加载条 |
| **P2** | **世界必须是数学上的环面：196 米为周期的程序化地形与林木。玩家往前走永远回不到"新地方"，也永远出不去。要求：地形高度、树的分布、草的分布全部是坐标的周期函数，穿越边界时画面零跳变。不许用"雾把接缝盖住"这种取巧。** | `noise.js` / `forest.js` / `director.js` 回绕 | 写一个 `?debug` 日志打印每次回绕前后 0.5 m 内的实例数，两次必须完全相等 |
| **P3** | **加浓雾。指数雾，能见度约 40 米；阴天，没有太阳，只有一盏手电。森林必须全是枯树——细高、无叶、枝桠下垂。要有水汽、落叶、湿泥地面。整体降饱和，脏。** | `atmosphere` 段 + `props.js` | 出三张截图：正前方 / 抬手电 / 抬头看天。三张里都不该看见地平线 |
| **P4** | **加一个身影。它第一次出现必须说不清是什么——雾里一个太高的竖条，你看第二眼它就没了。规则：你盯着它，它消失；你不看它，它以每秒 1 到 4 米靠近你。它只在移动、转身或久站时出现，而且永远先出现在你视野边缘。** | `entities/stalker.js` + 导演规则 R1–R6 | 导演日志能打印出每次显形的**触发规则、距离、你是看向还是移开** |
| **P5** | **它每次出现都要比上次近。用一个固定台阶表：78、64、52、42、34、27、21、16、12、9、6.5、4.5 米。被你看走或自然消失都往前走一格。到 4 米以内触发唯一的贴脸——然后黑屏，把玩家丢到林子里另一个位置，进入更糟的一轮。** | 阶梯 + CLIMAX | 连玩 3 轮，每轮第一次显形距离必须严格递减 |
| **P6** | **声音是主旋钮。它越近，环境声越小越闷，呼吸声越大越快，心跳进画面，低频嗡鸣增强。用一个 tension 值统一驱动：环境底噪增益 1.0→0.08 且低通 18k→380Hz，呼吸 0→0.9 且速率 0.22→1.05Hz，心跳 52→140 BPM。全部程序化合成，不加载任何音频文件。** | `audio/audio.js` | 输出一张 tension 0 / .25 / .5 / .75 / 1 五档的**频谱截图**或参数表 |
| **P7** | **补上轮回的感觉：一个残破石龛，固定在环面某处，玩家每绕一圈就会再遇到它一次。每绕一圈，它更破、更暗。同时屏幕角落的距离数字一直在涨，字幕每隔几圈说一句话。** | `world/landmark.js` + HUD | 走满 3 圈，地标必须明显变化；字幕必须出现且不重复 |

## 3. 分阶段任务链

见 `docs/TASKS.md`（P0–P8，每阶段含「目标 / 验收 / prompt / 反模式」）。

主线顺序不可乱：**先让"走不出去"成立（P1–P3），再引入"它"（P4–P5），最后加声音（P6）。**
> **反模式**：一上来就做身影和音效。那样你得到的是一个"有鬼的普通场景"，
> 而不是"一个困住你的地方，而这里恰好有鬼"。**地基是空间，不是怪物。**

## 4. 迭代修复 prompt 库（日常 99% 的真实形态）

恐怖项目有它自己的一类"哪里不对"。这张表可以直接抄：

### 4.1 空间 / 方向感

| 症状 | Prompt 模板 |
|---|---|
| 感觉像"无限地图"，还能分辨方向 | `玩家仍然能建立方向感。检查环面周期与雾能见度的比值，周期必须至少是能见度的 4 倍，且树的格点抖动要加大到看不出网格` |
| 转身时画面跳了一下 | `回绕瞬间有位移误差。检查摄像机位移量与地形网格对齐位移量，两者必须逐帧严格相等` |
| 一眼认出"这棵树刚才见过" | `重复太明显了。给树增加第三个哈希维度做局部扰乱，但**不许破坏周期**` |

### 4.2 身影 / 恐惧

| 症状 | Prompt 模板 |
|---|---|
| 一眼就看清是什么了，不吓人 | `它第一次出现太清楚了。降低不透明度、加大距离、并把它的轮廓压得更窄，让人只能看出"是个很高的东西"` |
| 出现得太容易看到 | `触发方位不对。它必须总是先出现在视野边缘，偏航两侧 0.25~0.85 弧度之间，不许摆在正前方` |
| 玩家学会了"一直盯着就行" | `给注视加代价：每次因注视而消失，阶梯必须前进，并且下一次显形的冷却时间缩短` |
| 贴脸出现太频繁 | `CLIMAX 只能是每阶段一次。检查触发条件，4 米以内才允许，并且触发后必须换一个阶段` |
| 它移动时被看到了 | `它只允许在 |视线夹角| > 26° 时移动。检查更新顺序，必须在计算夹角之后再决定是否推进位置` |

### 4.3 声音

| 症状 | Prompt 模板 |
|---|---|
| 声音切换有咔哒声 | `所有音量变化改用 setTargetAtTime，时间常数 0.35 秒，禁止直接赋值` |
| 呼吸听起来像白噪声 | `呼吸的包络不对。用非对称波形整形做出吸气短、呼气长的形状，带通中心提到 520 Hz、Q 1.1` |
| 张力上来了但没压迫感 | `提升低频：加入 41.2/41.9 Hz 的双正弦拍频，并让全局低通在 tension 0.8 时降到 500 Hz 以下` |
| 环境声"变小"变成"消失" | `环境底噪不要降到 0.08 以下，它是"闷"不是"停"。让低通承担大部分削减` |
| 显形没有预兆 | `违反预兆纪律。显形前 0.4 秒必须有一次 crack 或呼吸速率突变，加进去` |

### 4.4 性能 / 手感

| 症状 | Prompt 模板 |
|---|---|
| 帧率低 | `按 pass 报出帧时间。先砍雾中不可见实例的更新频率（隔帧更新），再考虑降树的数量` |
| 走路像飘 | `加点加速度和阻尼，加速度 26、阻尼 9。加头部摆动，幅度与速度挂钩，并绑脚步音` |
| 碰撞穿模 | `树干碰撞半径太小。用 `config.player.radius + 树半径`，并且推离要用插值，避免抖动` |

### 4.5 那条万能兜底（Tidewater 作者的风格）

```
这里看着怪，<具体哪里怪>，参考<真实参照物>，改成<那样>。
```

> **核心口诀**：不说"帮我优化恐怖感"，而说"**这一步**不够怕，因为**它太清楚了**，改成**再远 15 米并且只有轮廓**"。
> 恐怖游戏里，**你能准确说出"哪里不够怕"，比你能写出代码重要得多。**

## 5. 验证体系（恐怖项目专用）

图形项目验证"像不像"。恐怖项目必须验证**"什么时候发生"**。

1. **世界可复现性**：`?seed=` 固定种子，`worldAt(x,z)` 是纯函数。
   验收：写个脚本随机取 200 组 `(x,z)`，两次运行结果必须逐位相等。
2. **环面无缝性**：`?debug=wrap` 打印回绕前后 0.5 m 内的实例签名（位置哈希和）。
   验收：两次签名完全一致。**这是整个项目最重要的一条测试。**
3. **显形日志**：每次显形/消失打印 `[t=142.3s] rule=R2 dist=64→63.1 stared=false index=2`。
   验收：把 10 分钟日志导出，画出"距离 vs 时间"曲线，必须单调台阶下降。
4. **声音曲线导出**：每个 tension 采样点写出参数表（`materials/AUDIO-DESIGN.md` 那张表就是产物）。
   验收：人工对比曲线与设计表，误差 < 10%。
5. **首帧时间**：< 1.5 s。禁止加载条。
6. **帧时间预算**：按 pass 打印（`?stats`），地形 ≤3ms / 森林 ≤4ms / 雾雨 ≤2ms / 实体 ≤0.5ms。

> 一句话：**图形项目让 agent 看见"画了什么"，恐怖项目还要让它看见"在第几秒发生了什么"。**

## 6. 成品总提示词上下文（可直接粘贴给任何 agent）

```markdown
# 任务
做一个浏览器端第一人称恐怖短片游戏「雾林回环」。Three.js(WebGL2) + Vite + 纯 ESM，
依赖只允许 three，零外部素材（几何、贴图、音频全部程序化生成）。
目标是你能交付的最好的森林恐怖体验——不靠跳脸，靠"玩家开始不确定自己看见了什么"。

# 核心机制（三条，缺一不可）
1. 【走不出去】世界是数学上的环面：196 米为周期的程序化地形与枯林。
   地形高度、树、草全部是坐标的周期函数，穿越边界画面零跳变。
   浓雾（指数雾，能见度约 40 米），阴天无太阳，只有手电。
   玩家会真的绕圈，且因为雾看不见"重复"的全貌。
2. 【那个身影】一个只在你视线之外移动的东西。
   - 触发：1.2 秒内累计转身 > 2.2 rad / 连续前进 46→17 米 / 静止 7 秒（背后）/
           每次回绕必触发 / 每秒 2%×(0.4+恐惧值) 的环境骰子
   - 显形必须在视野边缘（偏航两侧 0.25~0.85 rad），不许摆正前方
   - 规则：你盯着它 1.1 秒 → 它消失；你不看它 → 它以 (1.1+3.2×恐惧值) m/s 靠近
   - 每次出现更近。台阶表：78 64 52 42 34 27 21 16 12 9 6.5 4.5 米
   - 距离 < 4 米 → 唯一一次贴脸 → 黑屏 → 换位置 → 进入更糟的一轮
3. 【声音是主旋钮】用一个 tension = max(恐惧值, 1 - 身影距离/80) 统一驱动：
   环境底噪 增益 1.0→0.08 / 低通 18k→380Hz（"闷住"而不是"静音"）
   呼吸 0→0.9，速率 0.22→1.05 Hz（12→63 次/分）
   心跳 0→0.55，52→140 BPM；次声 41.2/41.9Hz 拍频 0.1→0.8；耳语层中后期进入
   全部用噪声源+滤波器+LFO+波形整形合成，音量变化一律 setTargetAtTime。
   显形前 0.4 秒必须有声音预兆。

# 叙事与轮回
一个残破石龛固定在环面某处，每绕一圈就再遇到它一次，且一次比一次破。
HUD 只有一个不断增长的距离数字；每绕一圈字幕说一句逐圈加重的话。
CLIMAX 之后不是通关，是下一段更糟的循环。

# 铁律
- 第一次出现必须不完整：只有轮廓、只有声音、只在余光里
- 声音先于画面 0.4 秒；唯一的贴脸是 CLIMAX，每阶段仅一次
- 静默是武器：张力最高时不是最吵，是环境声几乎消失
- 恐惧必须来自玩家的选择（他自己转头 / 他自己决定不看）
- 代码风格 Tab / 单引号 / 分号；可调数字全部进 config.js，无魔法数字
- 目录即架构：core / world / entities / player / audio / game / ui
- 后处理用 DOM 叠加层（SVG 噪声颗粒 + 径向暗角 + CSS 降饱和），不用 EffectComposer

# 验证（必须交付证据，不许口头保证）
1. 环面无缝：?debug=wrap 打印回绕前后 0.5m 内的实例签名，两次必须一致
2. 显形日志：每次显形打印 [t] rule= dist= stared= index=，10 分钟曲线必须单调下降
3. 声音曲线：tension 0/.25/.5/.75/1 五档参数表
4. 首帧 < 1.5 秒，无加载条
5. 关键改动留截图到 out/

# 工作方式
我先描述目标和不满意的点，你负责全部实现、验证与修复。
每完成一阶段，用截图 + 日志给我看，再继续下一阶段。
```

## 7. 规模与成本对照

| 项 | Tidewater（参考对象） | 本项目（原型） | 本项目（完整版预估） |
|---|---|---|---|
| 类型 | 明亮 / 开放 / 系统驱动 | 黑暗 / 封闭 / 导演驱动 | 同左 |
| 代码 | 210 文件 / 83,509 行 | ~20 文件 / ~3,000 行 | ~60 文件 / ~12,000 行 |
| 资产 | 54.3 MB | **0 B（全程序化）** | 0 B（可加 CC0 采样音） |
| 测试 | 49 个测试文件 | 环面签名 + 显形日志 | + 声音曲线回归 |
| 最大难点 | FFT 海洋与 TAA | **环面无缝性** | 恐怖节奏调优（无法自动化） |

> **和 Tidewater 最大的不同**：那边的难度是**技术性**的（FFT、TAAU、级联阴影），
> 这边的难度是**节奏性**的。技术上它简单得多——20 个文件就能跑起来。
> 但"第几秒该发生什么"这件事，**AI 做不了，必须你来听、来走、来被吓**。
> 这就是为什么本项目的 prompt 里塞满了**阶梯表和映射表**：
> 把无法自动化的审美判断，翻译成可调的数值。
