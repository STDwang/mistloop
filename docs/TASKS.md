# 阶段任务链 · 雾林回环

> 把「一句话想法」翻译成 agent 真正能执行的任务链。
> 每阶段四段式：**目标 → 交付物 → 验收 → prompt → 反模式**。
>
> **顺序不可乱**：先让"走不出去"成立，再引入"它"，最后加声音。
> 反模式（最常见翻车方式）：**一上来就做鬼和音效**，结果得到一个"有鬼的普通场景"，
> 而不是"一个困住你的地方，而这里恰好有鬼"。

## P0 · 地基：引擎与数值表

```
目标：一个能渲染浓雾森林的最小骨架，1.5 秒内出画面。
交付：core/engine.js（渲染器/相机/主循环/自适应分辨率）
      core/rng.js（确定性哈希）、core/noise.js（周期噪声 fBm）
      core/input.js（指针锁/键盘/鼠标增量/转身累积量）
      config.js（唯一数值表）
验收：npm run dev 打开即有画面；resize 不崩；FPS 计数可见。
prompt：
  「搭一个 Three.js + Vite 的最小骨架：渲染器（像素比上限 1.25、
    ACES 色调映射）、透视相机、固定步长主循环、resize 处理。
    另外实现两样地基数学：确定性整数哈希（用于世界生成可复现）、
    以及"以固定周期为周期"的值噪声 fBm——注意是周期噪声，
    八度频率必须取整数倍，格点索引要对频率取模。
    全部可调数字集中到 config.js，代码里不许出现魔法数字。」
反模式：不要在这一步引入任何后处理链。DOM 叠加层就够，EffectComposer 会拖慢首帧。
```

## P1 · 空洞：环面世界（本项目的地基，最难的一块）

```
目标：196 米周期的地形与枯林。玩家走多远都回到"同样的地方"，且看不出来。
交付：world/terrain.js（周期性高度场 + 顶点色 + 网格对齐吸附）
      world/forest.js（实例化枯树 + 碰撞体 + 视锥半径刷新）
      world/undergrowth.js（蕨草/落叶广告牌）
验收（三条全部要过）：
  ① 无缝性：?debug=wrap 打印回绕前后 0.5m 内的实例签名，两次**逐位相同**
  ② 复现性：worldAt(x,z) 随机取 200 组，两次运行结果完全一致
  ③ 视觉：出三张截图（正前/抬手电/抬头），三张里都看不见地平线
prompt：
  「把世界做成真正的环面，不是"用雾盖住接缝"。
    地形高度用周期 fBm；树的分布用格点哈希，格点索引先对 K 取模
    （K × cell = 196）再哈希。地形网格每帧对齐到 round(p/196)×196，
    这样回绕时摄像机位移与网格位移严格相等，画面零跳变。
    树要用 InstancedMesh，随玩家移动刷新格子内的实例；
    同时维护玩家 14 米内的树干碰撞体数组。」
反模式：
  - 用"无缝地形 + 隐形墙"代替环面 → 玩家一撞墙就出戏
  - 用"分块无限地形" → 方向感可靠，恐惧无处立足
  - 树的密度做成 1.0 → 一眼看出网格
```

**这一阶段是整个项目成败的关键。其余阶段都可以返工，这一阶段不行。**

## P2 · 天气与雾：把能见度变成关卡设计师

```
目标：浓雾、阴天、湿泥、水汽、落叶、细雨。没有太阳。
交付：atmosphere 配置段 + world/props.js（雾团粒子 / 雾墙广告牌 / 雨 / 落叶）
      player/flashlight.js（窄角聚光 + 加性锥体体积光）
验收：截图里不该看见地平线；手电锥在雾中可见；雾密度可被 tension 提升
prompt：
  「用 FogExp2（密度 0.018~0.038）而不是线性雾。天空做暗绿灰的上下渐变，
    不放太阳。环境光用 HemisphereLight（地面色略暖）做出阴天漫射。
    手电是一盏 26° 的 SpotLight，半影 0.55，另加一个加性材质的锥体
    做出体积光柱（不用真体积光，太贵）。
    水汽用 Points + 程序生成的径向 alpha 贴图，永远围绕玩家漂移，
    坐标存相对玩家的局部空间——这样回绕时粒子不会跳。」
反模式：线性雾看起来像"贴了一张灰色图片"，没有纵深。
```

## P3 · 树林：从"能看"到"像"

```
目标：一片有压迫感的枯林。全部枯死——细高、无叶、枝桠下垂。
交付：forest.js 中的程序化树几何（树干 + 下垂枝桠，合并成单一 BufferGeometry）
      每棵实例：随机旋转/缩放/色偏 + 轻微倾斜
验收：截图里树木形成"拱廊"感，视野被压缩；远树随雾淡出而不是硬切
prompt：
  「森林必须是枯死的——有叶子的树会让场景显得有生机，与主题冲突。
    树干用细分圆台 + 顶点位移做出弯曲；枝桠是独立的小圆台，向下倾斜。
    每种树用 BufferGeometryUtils.mergeGeometries 合并成单个几何体，
    保证一个 draw call。用 InstancedMesh 的 setColorAt 做逐棵色偏。
    远处不要硬切——靠雾自然淡出即可。」
反模式：为了省事用 ConeGeometry 拼树，会看起来像圣诞树。
```

## P4 · 它：身影与规则

```
目标：一个"说不清是什么"的身影，按规则在你视野边缘显形。
交付：entities/stalker.js（剪影网格 + 呼吸缩放 + 不透明度控制）

验收：导演日志能打印每次显形的 触发规则 / 距离 / 是否被注视
prompt：
  「做一个极瘦的人形剪影，2.25 米高，纯黑，不受雾影响（fog:false），

反模式：把行为规则写进 Stalker 内部 → 后面调参要改两个文件。

## P5 · 导演：触发、阶梯、轮回

```
目标：整套"什么时候发生什么"的控制中枢。
交付：game/director.js
      - 环面回绕（回绕时计数 +1）
      - 恐惧值（随时间/轮次/每次显形上升，从不完全回落）
      - 天气与雾密度的阶段提升
      - 六条显形触发规则 R1–R6
      - 距离阶梯 78…4.5 与 CLIMAX
      - 地标腐坏阶段
      - 字幕播报
验收：连玩 3 轮，每轮第一次显形距离严格递减；导出 10 分钟显形日志曲线单调下降
prompt：
  「所有决策集中到 Director 一个类里：环面回绕、恐惧值、天气、显形规则、
    距离阶梯、地标阶段、字幕。Stalker 和世界都是被动的。
    显形规则共六条：转身累积、行进距离、久站（背后）、回绕必触发、
    每秒 2%×(0.4+恐惧值) 的环境骰子，以及方位必须落在视野边缘 0.25~0.85 rad。
    注视判定：视线夹角 < 4.5° 持续 0.35 秒累积 stareTime，超过 1.1 秒则消失。
    未被注视时它以 (1.1 + 3.2×恐惧值) m/s 靠近，但只在 |夹角| > 26° 时移动。」
反模式：把"注视消失"实现成"永远消失"→ 玩家学会一直盯着，游戏失去意义。
        **必须让它变成"延期"而不是"逃脱"**：消失要付出 sting 音效 + 阶梯前进的代价。
```

## P6 · 声音：主旋钮

```
目标：一个 tension 值统一驱动整个声景。
交付：audio/audio.js（全程序化合成 + 张力混音）
      materials/AUDIO-DESIGN.md 的映射表落地
验收：导出 tension 0 / .25 / .5 / .75 / 1 五档参数表；无咔哒声
prompt：
  「音频全部程序化，不加载任何文件。用一个 tension 值驱动：
    环境底噪（白噪→低通）增益 1.0→0.08、截止 18k→380Hz；
    呼吸（带通噪声 + 非对称波形整形 LFO）0→0.9，速率 0.22→1.05 Hz；
    心跳（52Hz 正弦 + 双峰整形 LFO）0→0.55，52→140 BPM；
    次声（41.2/41.9Hz 双正弦）0.1→0.8；耳语层中后期才进入。
    所有增益变化一律 setTargetAtTime(t, now, 0.35)，禁止直接赋值 .value。
    一次性音效：sting（3 个失谐锯齿下扫）、climax、crack、snap、footstep、bell。
    AudioContext 必须在用户手势后创建。」
反模式：
  - 环境声降到 0 → 那是"静音"不是"闷住"。让低通承担大部分削减。
  - 用 `.value =` 赋值 → 咔哒声，恐怖感当场归零。
  - 身影靠视觉先出现 → 违反"声音先于画面 0.4 秒"。
```

## P7 · 轮回与叙事：让它有意义

```
目标：把"打圈"变成叙事，而不是机制漏洞。
交付：world/landmark.js（残破石龛，按环面晶格复制，只渲染离玩家最近的一份）
      ui/hud.js（不断增长的距离数字、逐圈加重的字幕、氛围叠加层）
验收：走满 3 圈地标明显变化；字幕出现且不重复；暗角/颗粒/故障生效
prompt：
  「加一个残破石龛，固定在环面坐标上，按 2D 晶格复制，
    每帧只把离玩家最近的那一份摆到正确位置——这样玩家每绕一圈就会
    再遇到它一次。随轮次推进它有五个腐坏阶段（歪斜 → 更多碎石 →
    挂上破布 → 灯变红 → 有人站在那里）。
    HUD 只有一个不断增长的距离数字。每绕一圈一条字幕，逐圈加重。
    DOM 叠加层做氛围：SVG feTurbulence 噪声颗粒、径向暗角、
    CSS filter 降饱和；显形消失的瞬间给 canvas 加 260ms 的
    抖动/反相/色偏 class。」
反模式：把地标做成"唯一的一份、位置固定"→ 玩家绕一圈发现它不见了，机制当场穿帮。
```

## P8 · 收敛：性能与手感

```
目标：核显 720p 稳定 30fps 以上，操作不飘。
交付：自适应画质（按帧时间降实例刷新频率 / 像素比）
      手感：加速度 26 / 阻尼 9 / 头部摆幅与速度挂钩 / 脚步与摆动相位绑定
验收：按 pass 报出帧时间；连续 10 分钟无内存增长
prompt：
  「按 pass 报出帧时间。先砍"雾中不可见实例"的刷新频率（隔帧更新），
    再考虑降树的数量。像素比在帧时间 > 22ms 时降到 1.0。
    手感：加速度 26、阻尼 9，头部摆幅与速度成正比，
    脚步音在摆动相位过零点触发；奔跑消耗体力并**加快呼吸**——
    逃跑本身要让玩家更响。」
反模式：只降"画质"不降"看不见的开销"。要降就降玩家背后和雾里的东西。
```

## N 批 · 用户反馈修正（会话内追加）

### N1 · 世界比例修正 ✅
```
反馈：「主视角下人物的高度似乎只有小孩的身高」
诊断：探针实测相机离地 1.6600 m = CFG.player.eye，眼高本来是对的；
      问题在世界 —— 树 10–28.6 m、蕨类到胸口，参照物整体偏大 30%，
      大脑读出"我变小了"。
修正：树干 14–22 → 11–17 m，实例缩放 [0.72,1.3] → [0.74,1.14]，
      蕨类几何高 0.9 → 0.62，枯草 1.25 → 0.72，灌木 1.15 → 1.1。
验证：tools/scale-probe.mjs（22 PASS）+ tools/scale-verify.mjs（6 PASS，
      读渲染器真实实例矩阵）。
```

### N2 · 真实的脚步声 ✅
```
反馈：「脚步声只有"登登登"，不真实」
根因一（零抖动）：固定 1100 Hz 带通 + 固定 74→48 Hz 躯干 + 固定电平。
根因二（伪随机原料）：噪声 buffer 是同一个对象且 start 不带 offset，
      每个音效都从 t=0 起播 —— 探针实测路面两步波形相关 0.985。
根因三（暗原料）：780 Hz 之后的噪声原料上，1.7–3.2 kHz 的碎裂拿不到能量。
根因四（总线墙）：masterLF+masterWall 两道低通把亮瞬态削掉约 12 dB。
修正：三层随机（电平 ±15% / 音高 ±8% / 左右脚 ±6%）+ 路面/林地双地表
      + 亮噪声通道 noiseLPBright:5500 + fx 支路绕过总线墙
      + 噪声相位随机循环移位 + 路面"拍"的中心频率也随机（620–1240 Hz）。
验证：tools/step-probe.mjs（9 PASS / 0 FAIL）。含两次断言自身的教训：
      先用 high>low×0.5 判 FAIL（对物理正确的闷响不成立），
      再改"林地 high/low ≥ 路面 100 倍"又 FAIL（实测 93 倍）——
      连续两次把阈值调到刚好卡住实测值，说明错的是指标不是阈值。
      最终改用尾段比（时域包络，无跨频带相除）+ 相邻采样跳变占比。
```

### N3 · E 手电 / F 视角 + 第三人称 ✅

反馈：「改为e是开关手电，f是切换主视角，第三视角（俯视主人公）」
交付：E=手电（高频操作放左手食指自然落点），F=视角切换；

### N4 · 移动姿态（Shift 静步 / Ctrl 蹲下）✅
```
反馈：「按住shift为静步，按住ctrl为蹲下」（原始批次第 3 条的另一半）
设计核心：姿态必须有机制回报，否则只是个慢速惩罚，没人会用。
  · noiseLevel（响度 0–1）是姿态与游戏机制的唯一接口：
    静步 0.22 / 蹲下 0.12。director 用它加权 sinceTravel ——
    静步走 10 m 对"连续行进"触发规则的贡献只相当于正常走 2.2 m。
  · 脚步力度乘 (0.25 + 0.75×noise)，永远留一点声音（完全无声更假）。
  · 眼高/速度/步幅/摆动全部按同一个进度插值（3.2/s ≈ 0.3 s 完成），
    起身是"一个动作"，不是四件同时发生的事。
  · Shift 被静步征用后，奔跑改为"按住 W 一段时间自动升格"：
    恐惧驱动加速，松开即停 —— "停下来听"是零成本动作。
  · 第三人称下化身必须真的下蹲（躯干下沉 0.42 m + 前倾 + 屈膝），
    只降相机的话人偶会站着滑走。
踩坑：化身躯干下沉量 v1 写成正数 —— 蹲下时人偶反而升起 0.4 m，
      第一人称看不见、只有第三人称暴露，由 stance-visual 探针量出。
验证：tools/stance-verify.mjs（11 PASS / 0 FAIL，含 director 加权实测 6.1×）
      + tools/stance-visual.mjs（5 PASS / 0 FAIL，站立头顶 1.81 m /
      蹲下 1.36 m，附 out/stance-*.png 截图）。
```

### N5 · 乌鸦与昆虫（深山动物声）✅
```
反馈：「环境声需要丰富，需要不定时的有乌鸦，昆虫等深山里动物的声音」
立场（决定了整套参数的方向）：动物声是**张力计**，不是背景铺料。
  恐怖游戏里动物的正确用法只有一种：先用它标记"安全"，
  然后在它停下的瞬间让玩家意识到 —— 安全结束了。
  所以两个骰子的间隔都随 tension **拉长**，与 crack 相反：
    crack   [75 → 16] s   越危险越频繁（危险本身在逼近）
    crow    [25 → 150] s  越危险越稀少（连鸟都走了）
    insect  [14 → 65] s
  事件响度也同步衰减（crow ×(1−0.6·tension)，insect ×(1−0.5·tension)）。
  森林安静下来这件事，本身就是最响的恐惧信号。
合成：
  · crow —— 2–3 声**下行**嘶叫。亮噪声过窄带通，中心频率 0.16 s 内
    从 1150–1410 Hz 扫到 680–920 Hz，Q 8–12，峰值 0.05×power。
    "嘶哑"来自高 Q 窄带 + 快扫（谐波被逐个扫过），不是来自加失真。
  · insect —— 4.2–5.8 kHz 窄带 + 22–30 Hz 方波 AM，峰值仅 0.016。
    刻意压在脚步响度之下：虫鸣是"底纹"，不是"事件"。
踩坑（已加永久探针护栏）：第一版虫鸣把起音包络写在了方波 LFO 连接的
  同一个 gain 上。**已连接的 AudioParam 是"叠加"而不是"调制"** ——

### N6 · 顿挫诊断基建（"走着走着忽然闪我一下"）✅
```
反馈：用户报"走着走着忽然闪我一下"。这个描述指向三种完全不同的东西，
      必须先把它们分开 —— 而代码里**同时存在**三种嫌疑物：
        · 屏幕发白         → #flash 叠加层（hud.flash）或 glitch 的 invert(1)
        · 像是画面抽搐     → glitchCut 关键帧（0.3s steps(2)，8%处 invert+hue-rotate）
        · 画面卡住一瞬间   → 孤立长帧（帧率计数器看不见）
      排查后确认：hud.flash() 在全代码里**没有任何调用点**（死代码），
      所以"白闪"只可能来自 glitch 的 invert 那一帧。真正的元凶待用户确认。
交付（可复用的诊断基建，不是一次性排查）：
  · main.js 的 ftFrame：用 rAF 真实帧间隔统计 p99 / worst / 顿挫列表。
    【关键：不能用 engine.fps】它是 0.9 滑动平均，恰好把孤立长帧抹平 ——
    60 帧里 59 帧 4ms、1 帧 400ms，平均只有 10.6ms，看起来完全健康。
    p99 取 120 帧窗口；滞回阈 34 ms（低于 30fps 的界线）；冷却 0.5s 防刷屏。
  · 每笔顿挫记录**现场快照**：走了多远 / 阶段 / 张力 / 身影状态 /
    音频应变 / 音频节点数 / 画质档。只记"卡了多久"分不清成因。
  · engine.onFrameGap 钩子：必须在 _loop 取 now **之前**调用，
    因为 updaters 拿到的是被夹取的 dt（max 0.05s）—— 夹取正好会把
    400ms 的长帧显示成 50ms，要抓的东西被吃掉。
  · audio.strain()：呼吸/心跳/风/雨/环境 增益之和 = "此刻有多少声音在响"。
    它的唯一用途是在日志里分清「音频引起卡顿」和「卡顿引起爆音」——
    两者听起来可以一模一样，修法完全相反。
  · audio.nodeCount()：_noise() 里给每个 BufferSource 挂 onended 回收计数。
    源节点 stop() 后不会立刻摘出图，sting 一次铺开十几个；若浏览器某帧
    集中回收，就正好是"忽然一下"。
  · ?ft 查询参数控制是否输出顿挫日志（默认关，不污染正常游玩的控制台）。
踩坑：① ft.t 写成不存在的字段（时间戳在 ftTotal 里）→ 每次顿挫抛
      TypeError 打断 rAF，反而造成了真卡顿。这个 bug 是
      "诊断代码自己制造了它要诊断的现象"的教科书案例，被探针抓出。
      ② 断言阈值写 >100 帧，而 headless 软渲染 14 秒只有 36–54 帧 ——
      又是把真机数字当成了 headless 数字。降到 >25 并写清理由。
验证：tools/stutter-probe.mjs（7 PASS / 0 FAIL）。它刻意**不断言
      "有没有卡顿"**（SwiftShader 下 p99 天然 500ms+，断言无意义），
      只验证：诊断链路通、物理真在推进、节点数不发散、无泄漏趋势、无 JS 报错。
      真机判据：开 ?ft 正常游玩，控制台出现 [顿挫] 行即贴回来。
```
